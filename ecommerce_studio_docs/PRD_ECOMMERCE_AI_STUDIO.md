# 电商智能策划与生图工作台 (Ecommerce AI Studio) - 需求规格说明书 (PRD)

## 1. 文档概述
* **项目名称**：Ecommerce AI Studio（电商智能策划与生图工作台）
* **版本号**：v1.0.0
* **核心定位**：基于多模态大模型（Vision LLM）与多智能体（Multi-Agent）协同架构的**端到端电商营销设计工作台**。系统拒绝盲目生图，而是结合上传的真实商品图与商品信息，贯穿“买家痛点分析 $\rightarrow$ 具象场景推演 $\rightarrow$ 视觉与文案策略 $\rightarrow$ 人工二次干预 $\rightarrow$ 商业级电商图生成与预览”全链路。

---

## 2. 背景与核心价值
传统电商作图工具（如单纯使用 Midjourney 或 ComfyUI）存在严重割裂：
1. **缺乏商业洞察大脑**：无法主动分析消费心理、买家抗拒点和竞品短板，导致生成的场景往往浮于表面、缺乏销售转化力。
2. **缺乏人在回路（Human-in-the-Loop）**：大模型往往“一锤子买卖”直接出图，用户无法在中途干预文案、场景设定和构图 Prompt。
3. **命令行操作门槛高**：普通电商运营与设计师无法使用终端命令与代码。

本项目旨在通过**友好 Web 前端 + 多智能体商业思考中枢 + 多模态生图引擎**，实现“看得懂商品、懂买家痛点、能自主策划、支持人工微调、直接产出高清商用图”的完整闭环。

---

## 3. 功能需求规格 (Functional Requirements)

### 3.1 前端操作界面与工作台 (Web UI)
* **需求级别**：P0
* **形态要求**：采用现代化 Web 交互界面（推荐 Streamlit / Gradio），拒绝命令行操作。
* **界面功能分区**：
  1. **左侧：系统配置抽屉 (Config Panel)**：
     * 模型 Provider 选择（Gemini / OpenAI / DeepSeek / 本地 Ollama 等）。
     * API Key 与 Base URL 动态输入与持久化保存。
     * 各 Agent 的系统提示词（System Prompt）、角色目标（Goal）、任务指令在线编辑区。
  2. **中部：输入与多模态分析区 (Input Area)**：
     * 基础文本输入：商品名称、品类属性、目标消费群体、竞品差评或已知短板。
     * **多图上传组件**：支持拖拽上传 1~5 张商品实拍白底图/细节图（JPG/PNG），支持缩略图预览与删除。
  3. **下部/主工作区：两段式生成与二次微调区 (Interactive Pipeline)**：
     * **阶段一触发**：点击【AI 痛点挖掘与场景策划】按钮。
     * **可编辑文本域 (Editable Result Box)**：展示 AI 分析出的痛点分析、场景设定、宣传文案、英文生图 Prompt。
     * **人工干预 (Human-in-the-loop)**：用户可在文本框中直接修改文案、更换背景场景描述。
     * **阶段二触发**：点击【确认方案并开始生图】按钮，系统读取修改后的文案与 Prompt 触发生图引擎。
  4. **右侧/预览区：成果画廊与交付物 (Preview & Gallery)**：
     * 高清大图预览（支持缩放与细节查看）。
     * 生成历史对比（记录同一商品的不同策划版本）。
     * 一键下载图片（PNG/JPG）与一键导出完整策划案（Markdown）。

### 3.2 多模态商品图理解 (Multimodal Product Understanding)
* **需求级别**：P0
* **功能描述**：
  * 系统调用多模态模型（如 Gemini 2.0 Flash / Pro、GPT-4o）。
  * 大模型同时输入商品文字信息与用户上传的商品实物图。
  * 提取商品外观几何特征（外形轮廓、主体颜色、材质反光特性如磨砂/金属/透明玻璃、特有细节如显示屏/把手等），并将其作为硬性约束写入生图 Prompt。

### 3.3 多智能体角色分工 (Multi-Agent Team Workflow)
* **需求级别**：P0
* **角色配置**：
  1. **Agent 1：商品洞察专家 (Market Researcher)**
     * 职责：结合商品特征与竞品短板，输出买家抗拒点、核心痛点（如“担心漏水”、“保温时间短”），并提炼出第一杀手级卖点（USP）。
  2. **Agent 2：视觉创意总监 (Art Director)**
     * 职责：根据痛点推演具象使用场景（如“清晨拥挤地铁车厢”），设计构图动线、光影氛围，撰写攻注文案标语。
  3. **Agent 3：AI 制图工程师 (Visual Production Engineer)**
     * 职责：整合真实商品特征与视觉总监的构图要求，将其编译为符合商业摄影规范的高精度生图 Prompt，并调用生图工具。

### 3.4 灵活的 AI Provider 与提示词在线管理
* **需求级别**：P0
* **功能描述**：
  * 支持在前端直接配置模型连接参数，无需改动后端代码。
  * 支持修改 Agent 的 Prompt 后立即生效。
  * 支持在本地保存配置（持久化为本地 JSON 或 YAML 配置文件）。

### 3.5 图像生成引擎 (Image Generation Engine)
* **需求级别**：P0
* **首选引擎**：Google Gemini (Imagen 3, `imagen-3.0-generate-002`)，因其商业产品质感、真实光影渲染、英文文字排版优异。
* **备选引擎**：OpenAI DALL-E 3。
* **扩展能力**：支持后续挂载本地生图服务（如 ComfyUI API / FLUX）。
* **自动存盘**：生成后的图片需自动从流数据保存到本地 `output/` 目录并返回本地访问路径。

---

## 4. 交付产物规范 (Outputs)
每次任务完成后，系统必须生成以下两类确定性交付物：
1. **结构化营销策划报告 (`.md` / `.json`)**：
   * 痛点与卖点深度解析
   * 场景推演与故事线
   * 营销文案标语
   * 最终中英文生图 Prompt 记录
2. **高清商业级电商图 (`.jpg` / `.png`)**：
   * 比例规范：1:1 主图（1024×1024）或 3:4 详情图。
   * 存盘规则：按 `output/{timestamp}_{product_name}_{idx}.jpg` 命名保存。

---

## 5. 非功能性需求
* **响应与反馈**：各阶段生成时，前端必须有明显的加载指示器（Spinner / Progress Bar），并在界面打印 Agent 当前阶段的思考日志。
* **容错性**：如果生图 API 报错或超时，需在前台明确弹出报错原因，并保留当前策划案文本，允许用户修改后重试。
* **安全性**：本地配置文件（包含 API Key）仅保存在用户本地磁盘，不上传至公共服务器。
